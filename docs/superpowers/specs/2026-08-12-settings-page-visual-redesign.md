# 设置页视觉重构设计

## 目标

在不改变数据模型、Tauri 命令和功能语义的前提下，将设置页重构为紧凑、清晰、符合 macOS 工具型应用习惯的分组列表，解决横向失衡、纵向冗长、常驻编辑控件过多和危险操作视觉权重过高的问题。

## 参考原则

- Apple Human Interface Guidelines：减少设置数量、按相关性分组、使用熟悉的 macOS 控件、通过渐进披露隐藏低频细节。
- UI UX Pro Max：保持清晰层级、稳定间距、可见焦点状态、足够对比度和完整的 hover/disabled/error 状态；避免无意义渐变、大阴影和装饰性效果。
- 参考成熟产品的布局与交互模式，但保持 Skill Switch 现有视觉变量、应用图标和产品语境。

参考：

- https://developer.apple.com/design/human-interface-guidelines/settings
- https://developer.apple.com/design/human-interface-guidelines/disclosure-controls
- https://developer.apple.com/design/human-interface-guidelines/lists-and-tables
- https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/README.zh.md

## 页面骨架

- `.settings-page` 最大宽度为 `1040px`，在主内容区水平居中。
- 页面水平内边距为 `28px`，顶部内边距为 `28px`；窄窗口降为 `20px`。
- 标题区只包含“设置”和一句说明，不增加插画、徽章或装饰背景。
- 主体包含三个分组：支持的应用、应用目录、自定义分类。
- 分组间距 `20px`。分组使用白色或现有 `--panel` 背景、`1px` 浅边框、`10px` 圆角；不使用大面积灰色填充和强阴影。
- 分组标题区使用 `16px` 内边距；标题、说明和右侧操作在同一视觉层级内对齐。

## 支持的应用

- 使用紧凑矩阵，不把每个应用做成独立卡片。
- 宽屏为 4 列，中等窗口为 2 列，窄窗口为 1 列。
- 单项高度约 `44px`，包含应用图标、名称和右对齐 mini switch。
- 行项目仅在 hover 时显示浅色背景；选中状态只通过 switch 表达，不给整行铺品牌色。
- 保留现有 `role="switch"`、`aria-checked`、busy 禁用和点击行为。

## 应用目录

- 将当前“可编辑目录”和“固定目录”合并为一个“应用目录”分组，减少重复信息和卡片数量。
- 每行展示：应用图标、应用名称、状态、路径摘要、行尾操作。
- 原生数据源 Codex、Cursor、Zcode 显示“系统管理”或“固定自动可见”，路径只读，不显示输入框。
- Claude、Gemini、OpenCode、Hermes 在启用时显示当前路径和“修改”按钮。
- 默认态不显示输入框。点击“修改”后，仅当前行原位进入编辑态，显示输入框、“保存”和“取消”。
- 路径保持单行，溢出使用省略号；路径元素必须设置为完整路径的 `title`。
- 保存、错误处理和 busy 行为继续调用现有 `onSave`，不改变后端契约。

## 自定义分类

- 分组标题右侧提供“新建分类”按钮；点击后在标题下方显示单行创建区，包含名称输入框、“创建”和“取消”。创建调用现有 `api.createCustomCategory(name)`，成功后更新 `SettingsSnapshot`，不为任何 Skill 自动赋值，也不新增后端命令。
- 默认列表行只显示分类名称、`N 个 Skill` 使用数量和行尾 `···` 操作菜单。
- 不常驻展示输入框、“重命名”和“删除”按钮。
- 操作菜单只包含“重命名”和“删除”。删除使用危险色，其他选项使用普通文本色。
- 选择“重命名”后仅当前行进入编辑态，展示输入框、“保存”和“取消”；保存继续调用 `onRenameCustomCategory`。
- 未被引用的分类可直接删除；被引用或使用数量未知时，显示当前已有的内联确认区，并明确受影响 Skill 数量或“使用情况待确认”。
- 确认区继续使用可访问的内联 group，不伪装成没有焦点管理的 modal dialog。
- 空状态使用一句说明和“新建分类”操作，不显示高大的空白占位卡。

## 视觉规范

- 延续现有设计 token，不引入新依赖、外部字体或图标库。
- 主文字、次级文字、边框、背景、品牌色和危险色均使用已有 CSS 变量。
- 控件高度统一为 `32–36px`；设置行高度控制在 `44–52px`。
- 使用 8px 基准间距：`4 / 8 / 12 / 16 / 20 / 24 / 28`。
- 动画只用于 hover、focus、菜单和编辑态切换，时长 `150–200ms`；尊重 `prefers-reduced-motion`。
- 所有可点击元素有 pointer cursor；键盘焦点清晰可见；文本对比度满足 WCAG AA。
- 禁止渐变、大面积品牌色填充、玻璃拟态、强阴影、装饰插图和表情符号图标。

## 响应式行为

- `>= 1100px`：应用矩阵 4 列；目录和分类按完整行布局。
- `760–1099px`：应用矩阵 2 列；路径区域保留弹性宽度。
- `< 760px`：应用矩阵 1 列；目录和分类操作换至下一行；编辑态按钮保持可点击，不发生横向溢出。
- 页面缩放到常用窗口宽度时，不出现被截断的主要操作和水平滚动条。

## 代码边界

- 允许修改 `src/components/SettingsPage.tsx`、`src/styles.css` 和对应的 `src/App.test.tsx`。
- 为“新建分类”入口在 `src/App.tsx` 增加一个调用现有 `api.createCustomCategory(name)` 的最小回调，并通过 `SettingsPage` prop 传入；不得修改 `SkillInspector.tsx`、Rust 数据模型、Tauri 命令或 API 参数语义。
- 不改其他页面，不统一重构全局样式，不引入第三方组件库。
- 保留已有自定义分类创建、复用、重命名、删除、引用确认和错误反馈功能。

## 验收标准

- 2048px 宽截图中主内容视觉居中，不再挤在左侧并留下失衡空白。
- 首屏可同时看到三个设置分组的主要内容；页面高度明显低于当前版本。
- 自定义分类默认态没有输入框和成排操作按钮。
- 每个分类都可通过操作菜单进入重命名和删除流程。
- 应用目录默认态没有可编辑输入框；只有点击“修改”的行进入编辑态。
- 支持应用开关、路径保存、分类重命名和删除的现有测试不回归。
- 新增测试覆盖目录编辑态、分类操作菜单、重命名编辑态和删除确认。
- `pnpm test`、`pnpm typecheck`、`pnpm build` 和 `git diff --check` 全部通过。
- 必须运行实际 Tauri 页面并在至少 `1440×900` 与当前超宽窗口尺寸下截图检查；测试通过不能替代视觉验收。
